
# 问卷系统 MongoDB 数据库设计

本设计以用户、问卷和一次提交为三个独立存储单元，使用 users、surveys、responses 三个集合。题目与选项嵌入问卷，答案嵌入提交记录。概念有六类，不意味着必须建立六个集合。

## 1 概念关系与存储选择

### 实体概念

| 概念     | 建议的主要属性                                                                         |
| -------- | -------------------------------------------------------------------------------------- |
| 用户     | 用户ID、用户名、密码哈希、注册时间                                                     |
| 问卷     | 问卷ID、标题、说明、创建时间、状态、截止时间、是否允许匿名、是否允许重复填写、访问标识 |
| 题目     | 题目ID、题干、题型、顺序、是否必答、校验规则、跳转规则                                 |
| 选项     | 选项ID、选项文字、顺序                                                                 |
| 填写记录 | 记录ID、所属问卷、填写用户、是否匿名、提交时间                                         |
| 答案     | 所属填写记录、所属题目、所选选项或填写值                                               |

### 联系

用户创建问卷，用户填写问卷

用户     1 ── 创建 ── N 问卷
问卷     1 ── 包含 ── N 题目
题目     1 ── 包含 ── N 选项（选择题）
问卷     1 ── 对应 ── N 填写记录
用户     1 ── 产生 ── N 填写记录
填写记录 1 ── 包含 ── N 答案
题目     1 ── 对应 ── N 答案

## 2 逻辑结构设计

| 集合         | 一个文档代表什么 | 文档内部包含什么                         | 通过ID关联什么                               |
| ------------ | ---------------- | ---------------------------------------- | -------------------------------------------- |
| 用户集合     | 一个用户         | 用户名、密码哈希、注册时间               | 暂无                                         |
| 问卷集合     | 一份问卷         | 问卷属性、题目数组；选择题内包含选项数组 | 创建者ID                                     |
| 填写记录集合 | 一次提交         | 提交时间、是否匿名、答案数组             | 问卷ID、填写用户ID；答案中引用题目ID、选项ID |

### users集合

| 字段         | BSON 类型 | 默认与约束                                      |
| ------------ | --------- | ----------------------------------------------- |
| _id          | ObjectId  | MongoDB 生成的主键                              |
| username     | string    | 去首尾空格，1～50 字符，区分大小写，唯一        |
| passwordHash | string    | Argon2 哈希，禁止保存明文；输入密码 8～128 字符 |
| createdAt    | date      | 服务端生成 UTC 时间                             |

### surveys集合

| 字段           | BSON 类型              | 默认与约束                                  |
| -------------- | ---------------------- | ------------------------------------------- |
| _id            | ObjectId               | 问卷主键                                    |
| creatorId      | ObjectId               | 服务端从登录身份取得，引用用户              |
| title          | string                 | 去首尾空格，不能为空                        |
| description    | string                 | 默认空字符串                                |
| createdAt      | date                   | 服务端生成 UTC 时间                         |
| status         | string                 | draft、published、closed；初始 draft        |
| deadline       | date 或 null           | 发布时设置，必须是未来且带时区；null 不限时 |
| allowAnonymous | bool                   | 默认 false，匿名也须登录                    |
| allowRepeat    | bool                   | 默认 false                                  |
| shareToken     | string                 | 服务端随机生成，唯一，作为分享访问标识      |
| questions      | array<object></object> | 初始 []，发布至少一道题                     |

#### 嵌入题目和选项

| 字段       | 类型                   | 说明                                   |
| ---------- | ---------------------- | -------------------------------------- |
| questionId | ObjectId               | 稳定标识，插入或调整题序时不变         |
| title      | string                 | 非空题干                               |
| type       | string                 | single、multiple、text、number         |
| order      | int                    | 正整数，同一问卷唯一，上限 2147483647  |
| required   | bool                   | 默认 false；前端“是否可选”取反映射   |
| options    | array<object></object> | 仅选择题，至少两项；填空题不保存此字段 |
| validation | object                 | 与题型匹配的限制，详见关键逻辑说明     |
| jumpRules  | array<object></object> | 默认 []，从前向后首条命中生效          |

每个选项保存 optionId（ObjectId）、text（非空字符串）、order（正整数）。选项 ID、选项 order 在所属题目中唯一。题目 order 不要求连续；普通删除不重排，题前插入会顺移相关题序。

#### 嵌入跳转规则

| 字段             | 类型                          | 约束                                                               |
| ---------------- | ----------------------------- | ------------------------------------------------------------------ |
| operator         | string                        | single 用 selected；multiple 用 exactly；number 用 <、<=、=、>=、> |
| value            | ObjectId、ObjectId 数组或数值 | 按题型决定，选项必须属于来源题                                     |
| targetQuestionId | ObjectId 或 null              | 必须提供；后续题目或 null 结束                                     |

文本题不支持条件跳转。多选 exactly 表示所选集合完全一致，顺序无关，不是“包含其中若干选项”。

### responses集合

| 字段             | BSON 类型              | 约束                                         |
| ---------------- | ---------------------- | -------------------------------------------- |
| _id              | ObjectId               | 每次成功提交新建一条记录                     |
| surveyId         | ObjectId               | 引用问卷                                     |
| respondentId     | ObjectId               | 从登录身份取得，匿名也保留内部关联           |
| isAnonymous      | bool                   | 请求匿名时要求问卷允许匿名                   |
| submittedAt      | date                   | 服务端生成 UTC 时间                          |
| repeatRestricted | bool                   | 保存时为 not allowRepeat，供部分唯一索引使用 |
| answers          | array<object></object> | 仅保存当前路径实际填写的非空答案             |

答案包含 questionId 和以下二者之一：选择题用 selectedOptionIds（ObjectId 数组）；文本或数字题用 value（string 或有限数值）。非必答题空答案不保存。answer 没有单独主键，同一次提交中 questionId 唯一由业务逻辑保证。

管理接口把匿名记录的 respondentId 显示为 null；提交回执不返回任何填写者 ID。API 将所有 ObjectId 序列化为字符串、日期序列化为 ISO 时间。数据库 BSON 日期保存到毫秒，创建后读取持久化结果再返回。

## 3 文档结构示例

以下为 MongoDB Shell 风格结构示例：

```javascript
// users 中的一个用户
{
  _id: ObjectId("000000000000000000000002"),
  username: "alice",
  passwordHash: "$argon2id$...实际由服务端生成的密码哈希...",
  createdAt: ISODate("2026-10-18T00:00:00Z")
}
// surveys 中的一份问卷
{
  _id: ObjectId("000000000000000000000001"),
  creatorId: ObjectId("000000000000000000000002"),
  title: "年龄调查", description: "示例",
  createdAt: ISODate("2026-10-18T00:00:00Z"),
  status: "published", deadline: null,
  allowAnonymous: true, allowRepeat: false,
  shareToken: "实际由服务端生成的随机字符串",
  questions: [{
    questionId: ObjectId("000000000000000000000003"),
    title: "年龄", type: "number", order: 1, required: true,
    validation: {minValue: 0, maxValue: 120, integerOnly: true},
    jumpRules: [{operator: "<", value: 18, targetQuestionId: null}]
  }]
}
// responses 中的一次匿名提交
{
  _id: ObjectId("000000000000000000000004"),
  surveyId: ObjectId("000000000000000000000001"),
  respondentId: ObjectId("000000000000000000000005"),
  isAnonymous: true, repeatRestricted: true,
  submittedAt: ISODate("2026-10-18T01:00:00Z"),
  answers: [{questionId: ObjectId("000000000000000000000003"), value: 17}]
}
```

## 4 索引与一致性

| 集合      | 索引键                             | 约束或用途                                                       |
| --------- | ---------------------------------- | ---------------------------------------------------------------- |
| users     | username:1                         | 唯一，防止并发重复注册                                           |
| surveys   | shareToken:1                       | 唯一，通过分享标识定位问卷                                       |
| surveys   | creatorId:1, createdAt:-1, _id:-1  | 本人问卷列表及稳定排序                                           |
| responses | surveyId:1, respondentId:1         | 部分唯一，条件 repeatRestricted=true，名称 one_response_per_user |
| responses | surveyId:1, submittedAt:-1, _id:-1 | 按问卷筛选、按时间分页                                           |

每个集合还有 MongoDB 默认的 _id 唯一索引。题目及选项的唯一性、跨文档引用、题型限制由服务端验证，不是数据库外键或嵌入数组唯一索引。

索引由 app/main.py 的 prepare_database 在启动时创建。当前没有部署 MongoDB $jsonSchema 集合验证器；schema 通过 Pydantic 模型和业务检查实现。直接绕过 API 修改 MongoDB 可能写入不合法数据，因此不能把应用层校验等同于数据库强制约束。

题目/规则修改用原 questions 数组、草稿状态和创建者作为更新条件，单文档原子更新；冲突返回 409。基本信息修改也检查相关字段旧值及草稿状态。禁止重复提交依靠数据库条件唯一索引兜底，不能只依靠写入前查询。

## 5 设计理由与取舍

问卷定义通常整体读取，题目、选项和规则生命周期一致，嵌入有利于一次取得完整结构，也能在单文档更新中维护跳转引用。不同题型的 validation 与答案类型不同，MongoDB 对象与数组可以直接表达这种结构。

提交记录会随着填写增长，与问卷定义的增长速度不同，放入独立集合可避免问卷文档不断膨胀；一次提交的答案一起保存，避免拆成多条记录后产生不完整答卷。统计从 responses 实时聚合，不冗余保存选项人数、填写者列表或平均值，减少一致性维护。

关系数据库同样能够实现该业务，但若将用户、问卷、题目、选项、提交和答案全部逐表拆分，需要更多关联查询和跨记录更新。本项目按访问与更新边界选择嵌入加引用，而不是机械复制关系表结构。

当前适用于课程规模。超大问卷仍受 MongoDB 单文档大小限制，热点草稿并发编辑会发生冲突，统计随答卷增长需要进一步性能评估；尚未实现拆分问卷、统计缓存或问卷版本化。
