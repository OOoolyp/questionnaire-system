# 问卷系统关键逻辑说明

系统将配置校验、答案校验、跳转计算与提交保存分开实现。前端用于及时提示，后端负责最终可信验证。

## 1 生命周期与权限

- 问卷只允许 draft → published → closed。过期是 deadline 判断。草稿可编辑基本信息、题目和规则；发布前至少一道题，检查结构和引用并验证未来截止时间。
- 发布后问卷锁定，不能修改题目。
- 关闭后不支持重新发布和修改题目。
- 管理入口按照 _id 和 creatorId 查询，越权与不存在统一返回 404。

## 2 配置校验

QuestionInput 使用 type 作为区分字段选择对应 Pydantic 模型；规则按 operator 选择结构模型，再在业务层检查 operator 是否适合该题型。未知字段拒绝，因此不能向单选题塞入多选限制，也不能把题目编辑当成跳转规则编辑。

| 题型     | validation 字段                 | 配置与答案要求                                         |
| -------- | ------------------------------- | ------------------------------------------------------ |
| single   | {}                              | 至少两选项，有答案时只能选一个本题选项                 |
| multiple | minChoices、maxChoices          | 非负整数，最小≤最大，均不超过选项数；必答最多不能为 0 |
| text     | minLength、maxLength            | 非负整数，最小≤最大；长度按 Unicode 码点计数          |
| number   | minValue、maxValue、integerOnly | 有限数值，最小≤最大；整数限制下范围内需存在整数       |

未配置数量下限视为 0、上限视为选项数；未配置文本下限视为 0，上限不限；未配置数值边界时该侧不限。配置字段可省略；对适用的可选限制传 null 后保存时去除。不合法配置在写入前拒绝。

required 与范围限制分开处理：非必答题完全不填可跳过，即使设置了正数 minChoices 或 minLength；填写后则必须满足限制。

## 3 跳转规则及示例

| 来源题型 | operator        | value 的含义                                 |
| -------- | --------------- | -------------------------------------------- |
| 单选     | selected        | 一个选项 ID，选中即命中                      |
| 多选     | exactly         | 一个非空且不重复的选项 ID 集合，必须完全相同 |
| 数字     | <、<=、=、>=、> | 比较数字                                     |
| 文本     | 不支持          | 只能使用空规则列表                           |

规则顺序就是优先级。对合法非空答案依次判断，首条命中后立即取其 targetQuestionId；null 表示结束。未命中或非必答题为空，进入 order 最小的后续题；没有后续题则结束。目标题目必须属于同一问卷且 order 大于来源题，从配置上禁止向前、自己跳自己和循环。

## 4 编辑引用与并发保护

普通题目 PUT 完整替换题目配置，保留 questionId 和原跳转规则。希望保留的选项必须带回原 optionId；新选项省略 ID 由服务端生成。修改完成后重新检查全问卷跳转引用，删除被引用目标、移除条件使用的选项或改变类型/顺序破坏规则时返回 409，应先清空或修正规则。

## 5 完整提交校验

在前端页面填写时，不创建答题会话、不保存数据。真正提交时必须携带整份答案，从头验证；缺少当前路径必答题、附带跳过题、结束后题目或其他问卷题目均不写入。
提交在校验前和写入前两次检查可用性，第二次检查通过是接收时点。此后若关闭操作并行发生，已接收提交仍可能完成；当前没有跨集合事务来严格串行化关闭与提交。

## 6 匿名与重复提交

允许匿名不等于免登录。匿名记录内部保留 respondentId，创建者查看时隐藏该字段，内容接口只返回填写值与时间。禁止重复时 repeatRestricted=true，MongoDB 对 surveyId+respondentId 建立部分唯一索引，即使并发请求也只写入一条。允许重复时每次提交产生新记录，各自参与统计。

## 7 统计口径

通过 responses 的各统计指标实时计算。submissionCount 为成功提交次数，answerCount 为实际回答该题的答卷数。指标统计时以实际作答的答卷数为准
