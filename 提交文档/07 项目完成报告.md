## 1 项目目标与完成情况

本项目实现一个基于 MongoDB 的简化在线问卷系统，使注册用户能够创建、分发和填写问卷，并查看结果。项目重点是数据结构、后端业务、条件跳转、校验与测试，前端提供可直接操作的工作台和整页填写界面。当前已完成从注册登录、创建草稿、配置题目和规则、发布分享、填写提交到结果统计的完整闭环。

另完成草稿基本信息修改、题目前插入按钮和未保存提醒，便于实际演示。

## 3 MongoDB 设计

初始概念模型包含用户、问卷、题目、选项、填写记录与答案。实际持久化采用三个集合：

- users 保存一个用户；
- surveys 保存一份问卷及其题目、选项、校验与跳转；
- responses 保存一次成功提交及其答案。用户到问卷、问卷到答卷通过 ID 引用，问卷定义内部和答卷内部通过数组嵌入。

![image-20261022203009211](C:\Users\PC\AppData\Roaming\Typora\typora-user-images\image-20261022203009211.png)

这种选择符合读取和增长方式。问卷定义经常整体读取、共同修改，嵌入方便单文档原子维护；答卷会不断增加，独立保存避免问卷文档随提交持续增长；一次提交的答案一起写入，可避免部分答案成功、其他答案失败形成不完整记录。不同题型拥有不同结构，validation 和答案值可直接使用文档字段表达。

## 4 跳转设计

规则存储在 **`questions[].jumpRules`**。规则包含 `operator`、value 和`targetQuestionId`。

| 字段             | 类型                          | 约束                                                         |
| ---------------- | ----------------------------- | ------------------------------------------------------------ |
| operator         | string                        | single 用 selected；multiple 用 exactly；number 用 <、<=、=、>=、> |
| value            | ObjectId、ObjectId 数组或数值 | 按题型决定，选项必须属于来源题                               |
| targetQuestionId | ObjectId 或 null              | 必须提供；后续题目或 null 结束                               |

规则按数组顺序执行，第一条命中生效，未命中按 order 进入后续第一题，无后续题则结束。非必答题空答案不触发规则。目标必须属于同一问卷且位于后面，从而限制循环；文本题不支持条件跳转。

题目替换、删除和插入后重新检查引用。题目和选项 ID 保持稳定；删除目标、删除条件选项或改变题型破坏规则时拒绝修改。插入时只顺移题序，原跳转引用仍有效。题目数组更新匹配原数组和草稿状态，并发冲突返回 409。

## 5 校验与提交设计

校验步骤：

| 步骤                      | 什么时候检查               | 主要检查内容                                                 |
| ------------------------- | -------------------------- | ------------------------------------------------------------ |
| 1. 请求格式校验           | 收到请求时                 | JSON 是否正确、必填字段是否齐全、数据类型是否正确、有无不允许的字段 |
| 2. 身份与权限校验         | 访问业务接口时             | 是否登录、令牌是否有效；修改问卷或查看统计的人是否为创建者   |
| 3. 问卷状态校验           | 编辑、发布、填写和提交时   | 编辑对象是否为草稿；填写对象是否已发布、未关闭、未截止       |
| 4. 题目与规则配置校验     | 保存题目、跳转规则及发布时 | 题型与限制是否匹配、范围是否合理、选项和题序是否重复、跳转引用是否合法 |
| 5. 答案与完整路径校验     | 预览、填写及正式提交时     | 答案是否满足限制；正式提交是否符合从第一题开始计算的实际路径 |
| 6. 写入前及数据库约束校验 | 保存答卷时                 | 再检查状态与截止时间，通过唯一索引防止禁止重复时的并发重复提交 |

检验由谁完成：

- **前端后端都检查**：必答、选择数量、文本长度、数字范围等。前端及时提示，后端再次确认。

- **后端检查**：密码是否正确、令牌是否有效、当前用户是否拥有这份问卷。前端显示或隐藏按钮只是界面处理。

- **数据库保证**：用户名唯一、禁止重复填写时的并发唯一性。

## 6 填写结果统计设计

统计以成功保存的 responses 为准，采用 MongoDB 聚合实时计算，不维护独立计数缓存。各题型具体情况为：

- 单选统计各选项次数和实际回答数；
- 多选每个被选选项各计一次；
- 数字只对实际答案计算均值，无答案时为 null。跳过和未答不作为 0，实际填写 0 正常参与。允许重复时每份成功答卷分别计数。

## 9 遇到的问题与解决方法

| 问题                         | 原因与解决                                            |
| ---------------------------- | ----------------------------------------------------- |
| 创建后查询时间不完全一致     | MongoDB 毫秒精度；写入后读取实际文档再响应            |
| 登录令牌与分享标识含义混淆   | 分别命名 access_token、shareToken，迁移旧字段但保留值 |
| 题型与校验、跳转规则错配     | 区分模型约束结构，再检查题型、选项与目标引用          |
| 省略结束目标或 JSON 末尾逗号 | 结束明确传 null；移除尾逗号；增加 422 错误测试        |
| 修改题目破坏原跳转           | 保留稳定 ID，修改后整体验证，冲突拒绝写入             |
| 并发重复填写或插入覆盖       | 条件唯一索引及匹配旧数组的原子更新                    |
| Windows 前端模块加载失败     | 设置 .mjs JavaScript MIME、更新模块地址并提供加载提示 |
| 编辑后误离开丢输入           | 对比表单快照并统一拦截离开，保存成功后解除状态        |
