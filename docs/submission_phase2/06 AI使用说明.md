# 问卷系统第二阶段 AI 使用说明

使用工具：Codex。AI 参与需求讨论、方案对比、代码实现、测试执行、浏览器联调、演示数据准备和文档整理。本文件按实际对话归纳；Prompt 为用户原话摘录，Result 为工作概括，不把概括内容冒充完整原始对话。

第二阶段包括常用题与题目版本、题目复用、问卷版本、分享与题库、使用追踪与统计。

## 1 题目版本模型讨论

**Prompt：** “为什么不只增加一个集合，将版本作为一个属性，更新版本时只需新插入一个题目并版本增加1……或许还可以有一个来源属性指向来源哪一个题目（上一个版本的id）方便管理。”

**Result：** 讨论单一 questions 集合按版本存文档的方案，区分版本编号与实际修改来源。最终以 rootQuestionId 表示系列、parentQuestionId 表示实际修改来源，version 表示系列内创建序号，避免分支场景中把“上一个编号”误当成“父版本”。恢复时另记 restoredFromQuestionId。

**修改：** 提出单集合新插入版本，并接受父版本可指向较早版本的设计。。

## 2 查询版本与索引选择

**Prompt：** “建立两个常用题目集合，一个是母题……包含所有子版本的id……这样可以快速检索到所有版本，你认为怎么样”。后续：“好的，那我们记得建立联合索引。”

**Result：** 比较维护母体版本数组与按根 ID 查询的方案，采用同集合的 rootQuestionId＋version 联合索引。题目与问卷都建立系列版本联合唯一索引，分配版本时通过数据库唯一约束处理并发碰撞，避免应用层检查之后仍写入重号。

**修改：** 决定保留单集合设计和联合索引，不再新增“母题集合＋子题集合”。编号取系列最大值加一，父版本记录用户实际选中的来源；并发重试不改变父关系。

## 3 分享推荐与创建者权限

**Prompt：** “我希望分享时可以选择某个版本，被分享者可以选择使用该题的某个版本但更推荐使用分享时的版本。”以及“我希望还是只有创作者可以修改”。

**Result：** 把分享标识挂在具体题目版本上，入口固定推荐该版本，但允许查询同系列其他版本。将分享读取、作者管理与答卷权限分开：被分享者可以选用授权内容，不能编辑原作者题目或题库，不能由分享入口取得他人答卷。

**修改：** 推荐版本由创建者决定，不自动追随最新版本。

## 4 使用追踪的来源字段

**Prompt：** “某个题被哪些问卷使用……只能遍历了吧，你分析一下”。后续用户引用“可以查看题目被哪些问卷使用”“修改时可以决定是否创建新版本”，并提出“还是新建索引sourceQuestionId比较好吧”。

**Result：** 为问卷内复用实例保存具体 sourceQuestionId，并建立嵌入数组来源索引。查询引用时按具体版本直接匹配，按系列则先获得各版本 ID 后查询，不在题目文档反向维护问卷 ID 数组。

**修改：** 选择源题ID和具体版本作为联合索引。

## 5 分阶段实施与目录整理

**Prompt：** “明白了。接下来我们可以开始写代码吗？先列出一个计划”“进行文件整理，根据已有和即将有的内容，整理文件夹，符合项目规范”。

**Result：** 按基础模型与迁移、常用题版本、复用、问卷版本、分享题库、使用统计逐步实现，并同时接通相应前端。将身份、数据库准备、问卷业务、常用题与题库拆入 app/auth、app/core、app/surveys、app/library；前端拆为 pages 与 shared，测试归入 tests/backend 与 tests/frontend。

**修改：** 无

## 6 常用题版本与复用操作

**Prompt：** “检查第二阶段常用题与题目版本管理是否完成，若未完成继续完成”。随后：“执行题目复用 保存到常用题、指定版本加入问卷、切换版本、转为独立题 问卷编辑器中的保存、选题、版本切换操作”。

**Result：** 实现 app/library/questions.py 与版本路由，加入历史查看、派生和恢复。实现 app/surveys/reuse.py：问卷题另存为独立系列、后端复制具体版本快照、来源 ID 校验、保留实例 ID 的版本切换，以及 detach。编辑器增加保存、选题和切版操作；加入和切换重新验证必答、题型与全卷规则。

**修改：** 无

## 7 问卷版本管理

**Prompt：** “进行下一阶段问卷版本管理 从指定版本创建新草稿、查询历史 问卷版本列表、‘创建新版本’入口，文档要求同上”。

**Result：**  实现 app/surveys/versions.py 和专用路由，新增根问卷、父问卷和版本编号。指定来源复制为新草稿，生成新 ID 和填写标识，清空截止时间，保留题目及来源版本快照，不复制答卷。前端新增问卷版本列表和创建入口。

**修改：** 无

## 8 分享、题库与两个方向的选题

**Prompt：** “进行下一阶段分享与题库 分享访问、题库管理、收录与推荐版本 分享页面、题库页面、两个方向的选题流程”。

**Result：**  实现题库CRUD、收录项、分类排序、推荐版本、题目和题库分享访问；编辑器可进入题库选题，题库中也可选定版本加入问卷。外来原题可收录到私人题库，内部保留原授权并在后续使用时重验，响应不泄露授权凭据。

**修改：** 无

## 9 使用追踪与跨问卷统计

**Prompt：** “使用追踪与统计 查询引用问卷、跨问卷聚合 使用情况列表、统计结果和分布展示。在测试阶段不用测试结束后马上删除测试数据，我想在前端看看测试数据的前端效果”。

**Result：**  实现 app/library/statistics.py 与 analytics_routes.py，提供版本/系列引用列表，以及具体版本在本人问卷中的答案聚合。页面区分问卷版本数、根问卷数、引用处数、提交数与答案数，展示数字区间、选项比例、文本频次和按问卷拆分结果。

**自动发现与修复：** 对问卷复制后相同本地题目 ID 的情况，按 `(surveyId, questionId)` 成对匹配，防止不同来源版本混算。边界测试发现两个合法极大数求平均可能溢出，改用十进制聚合；数字分桶同样使用十进制处理0.3/0.1和负数边界。增加对应回归用例后再执行完整回归。

**修改：**  无

## 10 成果账号与启动说明

**Prompt：** “目前所有阶段结束，请在当前测试数据库的基础上，设计一个账号的数据用于展示目前的成果。”随后询问生成代码、库名是否是路径，以及从启动数据库开始还需做什么。

**Result：**  通过 scripts/seed_analytics_demo.py 与 scripts/seed_showcase.py 增量生成数据；完整展示以showcase账号为主，包含8个问卷版本、66份答卷、3个题库、7道题的11个版本，并安排分支、恢复、外来收藏、跳转及统计场景。用正式API生成真实答卷，没有直接写入虚构统计结果。生成过程记账，重复运行不重复提交。

**修改：** 旧测试和展示数据保留。展示夹具的只读验收位于 tests/backend/showcase_acceptance.py，不混入常规unittest计数。启动文档明确区分MongoDB磁盘目录、服务地址、逻辑库名和本地清单；已有数据重启不重新生成，首次空库初始化才按顺序执行两个脚本。
