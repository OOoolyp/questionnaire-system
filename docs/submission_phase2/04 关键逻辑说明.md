# 问卷系统第二阶段关键逻辑说明

第二阶段的主线是“把可复用内容保存为不可变版本，在问卷中保留已选版本快照，再以来源 ID 追踪引用和统计”。现有问卷中的临时题仍可独立嵌入，不要求全部入库。

## 1 题目系列、修改来源与版本号

`questions` 中一条文档代表一个具体版本，不另外建立“母题＋子题”两套集合，也不在母题里维护不断增长的子版本数组。

| 标识 | 含义 |
| --- | --- |
| `_id` | 一条具体题目版本的 ID |
| rootQuestionId | 该系列第一版的 ID，用于查询同一道题的全部版本 |
| parentQuestionId | 本次实际从哪个版本修改而来，不保证是编号减一 |
| version | 整个系列内的创建顺序号 |
| restoredFromQuestionId | 恢复时所复制内容的历史来源，普通派生时为空 |

第一版 rootQuestionId 等于自身 ID，parentQuestionId 为空。后续编号取系列当前最大 version＋1，与选择哪个父版本无关。例如已经有 Q1(v1)、Q2(v2)、Q3(v3)，从 Q2 再修改得到 Q4(v4)，则 Q4.parentQuestionId=Q2，而不是 Q3。

内容字段只有 title、type、options、validation。required、问卷内 order 和 jumpRules 取决于使用场景，不属于常用题内容。新题的 creatorId、根与父版本、编号、分享标识、时间全部由后端生成。

### 1.1 不可变范围

常用题版本没有覆盖内容的 PUT/PATCH，也没有删除版本接口。修改与恢复都插入新文档，旧问卷不受影响。sharingEnabled 是允许单独修改的访问配置，切换分享不会重写历史内容。

恢复会同时记录“修改来源”和“内容来源”：从 Q3 恢复 Q1 内容，生成 Q4，parentQuestionId=Q3、restoredFromQuestionId=Q1。并不把 Q1 或 Q3 原地覆盖，也不把问卷已有引用替换为 Q4。

### 1.2 选项身份

创建第一版时由服务端生成 optionId。派生时，客户端仅能带回父版本已有 optionId；新选项不带 ID，由后端生成。这样，保留选项身份时可继续验证旧跳转条件，删除或替换选项时能明确识别引用失效。恢复直接复制历史内容及选项 ID。

实现：`app/library/questions.py`、`app/library/schemas.py`。

## 2 版本分配与并发冲突

题目和问卷都采用“查询最大编号＋插入新文档＋唯一索引兜底”的方式分配版本：

```text
读取并固定本次指定的父版本快照
最多重复 16 次：
    查询该系列的当前最大版本号
    准备 max(version)+1 和新的 shareToken
    尝试插入
    若版本号或分享标识碰撞，重新取号/生成标识
    成功后读取 MongoDB 实际保存的文档并返回
重试耗尽：返回 409
```

联合唯一索引分别为 `{rootQuestionId:1, version:1}` 与 `{rootSurveyId:1, version:1}`；shareToken 各自有唯一索引。并发请求可有相同父版本，但不能产生相同系列内的重复编号。版本重试不会改掉实际父版本关系。

这一机制不是跨文档事务。每个版本是一次独立插入，重试失败不会留下半条文档；返回的时间以数据库保存值为准，避免 Python 与 MongoDB 时间精度不同造成响应和回读不一致。

## 3 问卷内快照与来源关联

一份问卷中的题目始终保留完整内容。对于可复用题目，额外保存 sourceQuestionId，指向 `questions._id` 的具体版本；独立题在持久化文档中没有该字段。

```text
常用题版本 Q2
    ↓ 后端复制内容
问卷 S1 的题目实例 A：questionId=A，sourceQuestionId=Q2，完整内容快照
问卷 S2 的题目实例 B：questionId=B，sourceQuestionId=Q2，完整内容快照
```

同一个版本可以出现在多份问卷，甚至同一问卷中出现多次，每次选用生成独立 questionId。questionId 表示问卷内的使用实例，不能与常用题版本 ID 混用。

### 3.1 加入与另存的方向不同

- **常用题→问卷**：后端核验来源授权，再复制固定版本，生成新实例 ID；不能由客户端提交伪造题干快照。可以追加或在指定题目前插入，后续题序顺移。
- **问卷→常用题**：提取内容字段，重新生成选项身份，创建属于当前用户的独立第一版。既不自动修改原问卷，也不自动添加 sourceQuestionId。已发布或关闭问卷也可另存，因为原问卷内容没有变化。

来源题是他人共享版本时，另存仍得到自己的独立副本，而不是取得原题的编辑权。之后的修改与来源系列互不联动。

### 3.2 来源内容保护

原题目编辑接口保留来源元数据，但不能借普通 PUT 改写引用题的题干、题型、选项或校验内容。应先创建来源新版本并切换，或转为独立题再修改。问卷专属的题序、必答及跳转配置按已有接口处理。

实现：`app/surveys/reuse.py`、`app/surveys/questions.py`。

## 4 切换版本与转为独立题

切换必须满足：当前用户拥有该问卷，问卷仍为 draft；页面传回的 expectedSourceQuestionId 与数据库一致；目标版本有有效授权，且与原来源属于同系列；新内容与当前 required 等问卷约束相容。

成功后替换内容快照与 sourceQuestionId，保留 questionId、order、required。默认复制原出站跳转规则，然后重新验证**整个问卷**。其他题指向本题的规则仍指向相同 questionId，不会因切换而自动断开。

如果新版移除了规则条件涉及的选项，返回 409 且不写入。客户端可以显式提交 clearJumpRules=true 清空本题出站规则后切换，但仍需通过全卷规则和题型校验。必答多选题不能切换到最多可选数为 0 的版本。

转为独立题采用相同归属、草稿和旧来源检查，仅移除 sourceQuestionId，保留内容与全部规则。第二次使用旧来源再次 detach 返回 409；成功转独立后，不再出现在原常用题的来源追踪中。

### 4.1 草稿原子写入

加入、切换和 detach 都先在内存中准备候选题目数组，再执行：

```text
匹配条件：问卷 ID＋creatorId＋status=draft＋读取时的旧 questions 数组
更新内容：新的完整 questions 数组
```

如果读取之后问卷已发布，或其他请求修改了题目数组，则 matched_count=0，返回 409，要求刷新。不会覆盖别人刚保存的内容，也不会把已发布问卷重新写成可编辑结构。并发追加允许部分请求冲突，但成功请求不能丢题或重复题序。

## 5 问卷版本与生命周期

`surveys` 中每条文档代表一个具体问卷版本。新版本只能通过专门接口创建，普通保存草稿不自动增加版本号。

从指定版本创建新版本时：

| 内容 | 处理 |
| --- | --- |
| 标题、说明、匿名与重复开关 | 从指定版本复制 |
| 嵌入题目、选项与跳转规则 | 深复制，保留实例与选项 ID，以及固定 sourceQuestionId |
| `_id`、shareToken、createdAt | 重新生成 |
| rootSurveyId | 沿用同系列根 ID |
| parentSurveyId | 指向实际选中的来源版本 |
| version | 系列最大编号加一 |
| status / deadline | draft / null |
| responses | 不复制，原答卷仍归原 surveyId |

草稿、已发布和关闭版本都可作为来源。旧版本状态不变，关闭的旧填写入口不会重新开放，新草稿入口不能填写。

题目实例 ID 在问卷版本之间保留，因此答卷定位必须同时包含 surveyId 和 questionId。原重复提交索引也依然按具体 surveyId 生效：一个用户在 v1 已填写，不妨碍在 v2 再填一次；在同一禁止重复的版本中再次提交仍冲突。

实现：`app/surveys/versions.py`、`app/surveys/version_routes.py`。

## 6 分享入口、推荐版本与所有权

题目分享和题库分享都是访问入口，不改变 creatorId。被分享者能读取和选择授权系列中的版本，不能修改作者原题或作者题库，也不能因此查看作者答卷。

题目 shareToken 附着于一条具体版本，入口推荐该版本；通过此入口可以查看同系列的其他版本，包括之后产生的版本。分享时推荐 v2，之后产生 v3，入口仍推荐 v2。题库的 recommendedVersionId 则独立决定各收录项推荐版本。同一道题的不同分享入口可以推荐不同版本。

每次读取、加入问卷、切换版本或收录时都核验入口仍有效，并验证题目根 ID 与授权系列一致。仅知道题目 ID、持有另一系列 token 或拥有已关闭分享链接，均不能使用目标原题。

### 6.1 撤销后的行为

- 关闭某入口后，基于该入口的新读取与新选用失败。
- 其他仍有效的同系列入口可继续授权；关闭一条链接不是将整个系列全面隐藏。
- 已使用问卷的内容快照、历史答卷及固定来源关系继续保留。
- 问卷作者可通过 source 接口查看自己已经使用的具体来源版本，不因此获得其他未使用版本的访问权。
- 草稿可将已有快照转为独立题；若要切到另一个外来版本，仍需提供有效授权。

系统按请求检查授权，但没有用跨集合事务把“撤销分享”和“已核验后的并发选用”完全串行化；不能据此声称撤销瞬间会回滚所有正在处理的请求。

实现：`app/library/access.py`、`app/library/share_routes.py`。

## 7 题库收录、外来收藏与条件更新

题库是创建者维护的集合，items 每项包含 rootQuestionId、recommendedVersionId、category、order、addedAt。按系列去重而不是按版本去重，所以选用其他推荐版本是更新原收录项，不是再插入一条同根题目。

更新已有项必须带回 expectedRecommendedVersionId；首次收录不能伪装成覆盖已有记录。order 在同题库内不能重复，推荐版本必须属于路径中的根题目系列。

对题库的更新和删除，写入条件包含读取时的 ID、创建者、名称、说明、items、sharingEnabled，防止读后被其他请求改动仍覆盖。此处是 MongoDB 单文档条件更新；嵌入数组的根 ID 与顺序唯一性由服务层检查，并非 MongoDB 对同一数组内部自动提供联合唯一约束。

### 7.1 私人收藏不是权限转移

自己的私人题库可以收录他人授权原题。内部 items.accessProof 保存原题或原题库的访问凭据，不向 API 响应返回。再次查看或选用时继续检查原授权；由自己的 bankId 访问也不会绕过授权。

原授权失效后，收录项保留，question 预览为 null，可以移除收藏，但不能再用其私藏凭据继续查看来源版本。题库列表、详情、共享响应都去除 accessProof。

含他人原题的私人题库不能开启分享，已经分享的题库也不能再收录他人原题，避免把私人收藏转为无限扩散的分享授权。若确实需要自己维护并分享内容，可以另存独立副本，获得新的根题目和归属。

移除收录项或删除题库会使该题库授权路径失效，但不删除 questions 文档，也不修改已复用的问卷快照。

实现：`app/library/banks.py`、`app/library/bank_routes.py`。

## 8 使用追踪与反向查询

不在题目版本中维护“被哪些问卷使用”的数组，而查询问卷嵌入题的 sourceQuestionId。索引 `{"questions.sourceQuestionId":1}` 支持此查询。

具体版本范围直接匹配一个来源 ID；系列范围先按 rootQuestionId 查出版本 ID，再对问卷来源执行 `$in` 匹配。聚合用 `$filter` 提取匹配的嵌入实例，用 `$facet` 同时计算总数和分页，区分：

- 问卷版本数：匹配的问卷文档数。
- 问卷系列数：根问卷去重数。
- 引用处数：匹配的嵌入实例总数，同一问卷可以大于一处。

题目作者可追踪全局引用；其他使用者必须已在自己问卷引用该具体版本，且只能查看自己范围内的记录。作者看到外部引用时，title 和 createdAt 为 null，canViewResults=false，避免泄露其他用户的问卷详情或答卷。

使用追踪包括草稿、发布和关闭问卷，是当前来源引用关系；不是“曾使用过后又移除”的历史审计日志。普通独立题或 detach 后的题目不再匹配来源 ID。

## 9 跨问卷聚合必须成对定位答案

聚合始终针对**一条具体常用题版本**和当前用户拥有的问卷。仅有分享链接不授予统计权限；题目作者也不能汇总别人问卷中的答案。

查询流程：

```text
找出本人问卷中 sourceQuestionId 等于目标版本的嵌入题
为每份问卷建立：surveyId → 该问卷中匹配的 questionId 集合
按本人这些 surveyId 筛选 responses
展开 answers，再按 (surveyId, questionId) 成对匹配
聚合总次数、选项、数字区间、文本和按问卷拆分结果
```

例如问卷 S1(v1) 与 S2(v2) 保留相同 questionId=A，但 S1.A 来源 Q1，S2.A 已切换到 Q2。如果只按 A 聚合，会把不同题目版本的答案混在一起；当前按 surveyId＋A 成对筛选，Q1 与 Q2 分别统计。同一问卷多处使用同一版本时，各位置都参与计数。

### 9.1 三种次数的区别

submissionCount 为涉及这些问卷的全部成功提交，包含未回答此题的提交。answeredSubmissionCount 为至少回答一处该版本的答卷数，每份只算一次。answerCount 为各匹配引用位置的有效答案数。

例如两份答卷各回答两处该题，则提交数=2、含题答案提交数=2、答案数=4。它们都不是去重人数；允许重复提交时每条记录分别参与统计。草稿可以贡献引用数，但没有实际答卷时不贡献答案数。

### 9.2 分布与数值边界

| 类型 | 规则 |
| --- | --- |
| single / multiple | 展开 selectedOptionIds 计数，按原选项补齐零次项；比例分母为有效答案数，多选合计可超过 100% |
| number | 忽略未回答，真实的 0 参与统计；给出均值、极值及 `[下界,上界)` 非空区间 |
| text | 按完全相同文本分组，按频次降序、文本升序取前 20 项，返回其他文本答案合计 |

数字桶采用十进制转换后除以区间宽度、向下取整，避免 `0.3/0.1` 的二进制边界偏差；负数也按向下取整分桶。最多返回前 100 个非空区间，另用第 101 个判断是否截断，截断不影响全量均值和计数。均值使用十进制聚合，避免两个合法 `1e308` 相加溢出，再转换为 JSON 可输出的有限数字。无有效答案时极值和均值为 null。

统计是实时聚合而不是预存累计计数，没有额外维护容易失配的反向数组。当前统计不包含跨用户答案共享、按人去重、任意历史审计、显著性检验或不同题目版本混算。

实现：`app/library/statistics.py`、`app/library/analytics_routes.py`。

## 10 兼容迁移与索引边界

启动时对完全没有问卷版本字段的旧记录补为 v1：rootSurveyId=自身 ID、parentSurveyId=null、version=1。若记录只含部分版本字段，启动会明确报错，要求修复，而不是擅自重置已有关系。重复迁移不改变原有题目、答卷和分享标识；旧 accessToken 在缺少 shareToken 时沿用原值重命名。

本阶段关键索引是两个系列版本联合唯一索引、题目及题库分享标识唯一索引、创建者列表索引和问卷来源多键索引。统计先按 surveyId 限制答卷，复用已有答卷查询索引。索引存在与查询结果已验证；测试结果不等同于大规模数据的性能压测结论。

实现：`app/core/database.py`。单文档更新提供并发保护，但多集合读取与统计没有事务快照隔离；请求期间持续写入时，不承诺整个页面各接口处于同一个全局时点。

## 11 前端交互与可信边界

前端提供常用题版本历史、问卷版本历史、题库管理、分享访问、编辑器双向选题，以及使用情况和分布页面。默认选择入口推荐版本，用户可以显式切换其他可读版本。

前端提示和过滤只用于交互，权限、版本同根、内容与跳转约束、旧来源检查均由后端再次验证。题干、问卷名和文本答案在渲染前转义。分享链接解析只提取入口类型与 token，业务 API 仍访问本应用，不向用户粘贴的外部网址发送授权请求。

保存失败不清空输入；离开未保存编辑或未提交填写时确认放弃。异步统计和引用分页使用请求序号及路由检查，忽略切换后迟到的响应。前端模块与样式使用版本参数处理缓存，修改公共模块时需维持统一导入地址，避免同一状态模块被重复实例化。

前端定位：`frontend/src/pages/` 中 library、survey-versions、banks、shared-library、question-analysis 页面，以及 `frontend/src/shared/` 中 reuse-picker、library-access、library-form、library-links 等模块。
